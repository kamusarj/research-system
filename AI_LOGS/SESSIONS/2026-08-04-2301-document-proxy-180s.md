## Decisions Made

- Treat HTTPX's 120-second provider setting as an inactivity timeout, not a total wall-clock budget.
- Set a bounded 180-second proxy default based on the observed 131.115-second successful request.
- Keep Retry explicit and reject both an unlimited proxy and automatic paid retries.
- Expose the timeout through Compose so runtime and build configuration agree.

## Verification Result

Pass. The exact failure was a 131.115-second API success racing a 125-second proxy reset. Runtime is
now configured and rebuilt at 180 seconds on the documented port, with current browser and provider
proof green.

## Known Issues

- A successful provider call can exceed the configured HTTPX inactivity timeout in total wall time.
  Calls repeatedly nearing 180 seconds should be moved to an asynchronous workflow rather than
  increasing the synchronous budget indefinitely.
- The first frontend recreation command omitted the shell-only `FRONTEND_PORT=13000` override and
  briefly bound the new container to `3000`. Read-only inspection caught it immediately; frontend
  was recreated again on `13000` and verified healthy. No API, worker, database or data changed.
